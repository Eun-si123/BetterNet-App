## 0. 프로젝트 최상위 목표

**BetterNet은 전 세계의 다양한 인터넷 환경에서 실제로 유용한 작업을 완료할 수 있게 돕는, 사용자 제어형 인터넷 기능 플랫폼이다.** 특히 매우 느리고, 계속 끊기고, 지연·손실이 크거나, 사용 비용이 높고 연결 수단이 제한된 네트워크에서 가치가 있어야 한다. 좋은 네트워크에서도 선택형 도구로 유용해야 한다.

프로젝트의 성공 조건은 서로 보완적인 네 가지다.

1. **실사용:** 웹 탐색, 메시지, 영상, 게임·통화, 파일 전송 등 *검증된* 작업이 실제로 더 잘 완료된다.
2. **정량 증거:** BetterNet OFF/직결과 ON을 동일 환경에서 비교해 성공률, 지연·지터·손실, 복구, 데이터·전력 비용, 악화 사례를 기록한다.
3. **자유로운 구성:** 기본 추천 설정은 쉬워야 하고, 사용자는 대시보드·기능 활성화·경로·서버·자원 정책을 안전한 범위에서 변경할 수 있어야 한다.
4. **신뢰·접근성:** 개인정보와 사용자 동의를 존중하며 저사양 장치·저속·종량제 연결, 다양한 언어, 자가 서버·커뮤니티 참여를 고려한다.

**하지 않을 약속:** 물리적인 연결이 없는데 인터넷을 만들어 냄, 무조건 낮아지는 핑, 모든 웹사이트의 TLS 콘텐츠를 임의로 압축/수정, 모든 검열망 통과, 완전 익명, 모든 앱의 중단 작업 자동 재개, 서버가 악성코드 없다는 절대적 인증.

## 1. Phase와 Milestone의 역할을 분리한다

- **Phase P0~P6 = 어떤 종류의 제품 문제를 해결하는 개발 영역과 순서.** 기존 PRODUCT_ROADMAP.md의 명칭을 유지한다. 서로 독립적인 보조 작업은 병렬 진행할 수 있으나 합격 판정은 생략할 수 없다.
- **Milestone M0~M9 = 실제 산출물 + 독립적 검증 + 실패 조건이 있는 통과 관문.** 코드 커밋 수나 CI 실행 수가 아니라 사용자에게 관측 가능한 결과를 기준으로 닫는다.
- **A0~A3 = 기존 MILESTONE_A.md의 가장 가까운 핵심 검증 관문.** 새 번호로 대체하지 않는다. M0↔A0, M1↔A1, M2↔A2, M3↔A3로 대응한다. 정식 검증 근거는 해당 문서와 STATUS.md에서 관리한다.
- **선택형 역량 E1~E7 = 비차단적 확장 작업.** 앱 안정판의 필수 관문으로 모두 묶지 않는다. 선행 안전 관문이 통과하고 독립적으로 검증한 후 기능별 출시한다.
- **BetterNet-private Phase 0~7 = 별도 비공개 연구용 Phase.** 공개 앱의 P0~P6과 이름이 비슷해도 합격 상태는 전혀 공유하지 않는다. 비공개 소스·로그·개인 식별 정보·배포 구성을 자동 이식하지 않는다.

## 2. Phase 0 — 안전한 Android 기반과 재현 가능한 배포

### M0 — 사용자용 안전 기반 (기존 A0)

**완료 후 사용자가 할 수 있는 일:** Android 앱을 설치하고 자신의 네트워크 상태, 제한과 앱별 선택을 확인할 수 있다. 아직 허용하지 않은 네트워크 포워딩이 절대 시작되지 않는다.

**구현 묶음**
1. 현재 main의 네트워크 표시/앱 선택 기능을 실기기와 코드로 재확인하고, Draft PR #7의 실제 포함 범위를 main과 혼동하지 않는다.
2. 최초 실행 안내: 앱의 실제 지원 상태, 현재 연결 종류/종량제 여부, 사용자의 선택·중지·기능 미지원 사유를 명확히 표시한다.
3. Android VPN 동의/다른 VPN 공존 안내: VPN 동의 전에는 어떤 포워딩도 시작하지 않는다. 선택 앱이 사라졌다면 전체 기기 적용으로 변경하지 않는다.
4. 한국어/영어 UI, 글꼴 크기·접근성·저전력 기본 설정, 오류 메시지, 오프라인에서도 볼 수 있는 도움말을 최소 범위에서 제공한다.
5. JVM 단위 테스트, Android Lint, APK 서명·체크섬·소스 SHA·비밀정보 검사, 문서 링크 테스트를 CI에 기록한다.
6. 앱 재설치/업데이트/중단/권한 거부/백그라운드 복귀/다른 VPN 실행/저장 공간 부족 등의 안전 경계를 명시하고 테스트한다.

**수용 기준 / 증거**
- 동일 소스 SHA의 APK가 CI에서 만들어지고 장치에 설치되어 실제 UI와 선택/권한 거부 동작을 증명한다.
- 미동의 시 외부 연결·VPN 생성이 발생하지 않고, 앱 선택 없이 전체 캡처되지 않는다.
- 손실 없는 안전 종료, 데이터/시크릿 외부 출력 없음, 기존 VPN을 자동 종료하지 않음.
- 최소 1개 실제 Android 기기에서 설치·시작·Stop·권한 거절/취소 테스트 PASS. CI 성공만으로 M0 완료 불가.

**실패 시:** 예기치 않은 VPN 시작/트래픽 캡처/시크릿 누출이 보이면 해당 경로 즉시 비활성화하고 재현 테스트로 회귀를 막는다.

## 3. Phase 1 — 첫 번째 진짜 인터넷 연결

### M1 — 선택한 브라우저의 실제 HTTPS 성공 (기존 A1, 최우선)

**완료 후 사용자가 할 수 있는 일:** 명시적으로 선택한 Android 브라우저의 실제 HTTPS 페이지가 BetterNet 경로를 통해 정상 열리고, 선택하지 않은 앱은 BetterNet에 캡처되지 않는다. 일반 인터넷 가속이나 VPN 전체 지원을 뜻하지는 않는다.

**구현 묶음**
1. **기존 코드 재검토:** Draft PR #7의 VpnService/TUN/패킷 처리/인증/기한·취소 코드를 모듈별로 검증. 실제 동작 부재를 새 추상화로 덮지 말고 필요한 구현·테스트 결함을 수리한다.
2. **Android 범위/권한:** 선택 앱 하나, 명시적 OS 동의, foreground service와 알림 Stop, 기존 VPN 충돌 진단, 서비스 종료와 리소스 청소.
3. **소켓 경계:** 비-VPN Android 네트워크에 바인딩되고 protect 처리된 게이트웨이 소켓, 서버 신원/TLS 검증, 인증 토큰의 안전한 취급, 만료·오류 처리, 타임아웃 공유 예산.
4. **허용 목적지 제한:** 초기는 승인된 테스트 HTTPS 목적지만. DNS 질의/응답 상관관계, A/AAAA, IPv4/IPv6, DNS 재바인딩·허용 도메인/주소/포트, 재귀 라우팅 차단.
5. **TCP/TUN 실제 전달:** SYN/ACK, 데이터 송수신, 재전송, FIN/RST, 윈도·역압, MTU/단편화 처리/거부 정책, 부분 쓰기와 취소/동시성. UDP/QUIC는 지원되지 않는 동안 정직하게 제외하고 경로를 알린다.
6. **독립 검증:** 승인된 격리 테스트 게이트웨이와 독립 HTTPS 호스트를 사용한다. 앱 화면에 받은 실제 응답과 목적지 서버가 확인한 요청을 대조하고, 선택하지 않은 다른 앱의 트래픽이 터널을 통과하지 않음을 확인한다.
7. **실패 케이스:** 인증 거부, TLS 이름/서명 오류, DNS 오답, 연결 중 Wi-Fi 끊김, 앱 강제 종료, VPN revoke, 화면 잠금/백그라운드, Stop 도중 I/O, 운영체제 재시작, 잘못된 패킷.
8. **회귀 묶음:** 정적 테스트 → JVM/루프백/네트워크 장애 시뮬레이션 → Android 에뮬레이터 → 실제 Android. 테스트 통과를 단계별로 별도 표기한다.

**필수 PASS 증거**
- 선정한 1개 실제 Android 앱 + Android/빌드 버전 + 소스 SHA + 게이트웨이/테스트 목적지 기록.
- 직접/BetterNet 각각 독립적인 HTTPS 결과 확인, 올바른 최종 응답과 인증된 중계 경로 증거.
- 선택하지 않은 앱은 터널 밖, 권한/신원 실패 시 안전 중지, 중지 이후 잔존 캡처 없음.
- 동일 시나리오 반복 PASS, 부정 테스트 PASS, 재현 방법 저장. 단순 TUN 패킷 생성·루프백 TLS 통신은 불충분.

**BLOCKER:** 실제 장치와 명시적으로 승인된 별도 테스트 게이트웨이가 없으면 M1은 NOT RUN/BLOCKED로 표시한다. 사용자 개인 홈서버를 암묵적으로 공개하지 않는다.

## 4. Phase 2 — 개선 효과를 실험으로 입증

### M2 — 실사용 가치와 한계가 수치로 입증됨 (기존 A2)

**완료 후:** BetterNet이 어떤 상황에서 작업을 더 잘 완료하는지, 언제는 직결이 더 나은지 증거로 설명할 수 있다.

**구현 묶음**
1. 실험 전에 성공의 정의를 정한다: 예를 들어 “선택 브라우저가 제한 시간 내 동일 테스트 페이지와 리소스를 완료” 등. 네트워크 프로필과 측정 방법도 먼저 기록한다.
2. 테스트 축: 정상/좋은 회선, 혼잡, 50/100/200 kbit/s 예시 저속, 큰 RTT(예: 150/800 ms), 랜덤·버스트 손실, 간헐적 단절(예: 10초·2분), Wi-Fi↔모바일 경로 전환, 다중 조건 조합. 이 값들은 **제안용 테스트 입력**, 효과 주장 아님.
3. OFF→ON과 ON→OFF 순서를 교차·무작위화하고, 동일 장치·앱·콘텐츠·경로 및 반복 시드/측정 시각을 기록한다. 반복 횟수는 효과 변동성에 따라 사전에 정하고 충분히 늘린다.
4. 성공률, 중단 횟수, 완료/재연결 시간, p50/p95/p99, RTT/지터/손실, TCP 재전송, 실제 송수신 바이트/오버헤드, CPU/배터리·종량제 사용 비용을 수집한다.
5. 브라우저부터 검증하고, 실제 메신저의 작은 메시지/미디어 전송, 영상 로딩 등을 프로토콜 지원 범위 안에서 추가한다. 게임·음성·QUIC/UDP는 자체 별도 게이트가 필요하다.
6. 실패 결과도 동일하게 기록한다. 외부 릴레이가 더 느리거나 불안정하면 직결 유지/추천, 자동 경로 변경 보류를 정식 결과로 인정한다.
7. 저사양 Android와 저비용 연결에서 CPU/배터리/디스크/탐지 트래픽 사용량이 과도하지 않은지 측정한다. 가짜 서버, 캐시 효과, OS 백그라운드 제한으로 인한 착시를 배제한다.

**필수 PASS 증거**
- 사전 정의한 조건에서 최소 하나의 **실제 사용자 작업 결과**가 반복적으로 유의미하게 개선되거나, 이전 실패 작업이 안전하게 성공하게 되는 근거.
- 동일 조건의 악화·무효·직결 우위 사례를 숨기지 않는 보고서.
- 데이터 비용·전력 비용·재현성 기록, 테스트 환경/표본 변동 설명.
- 단순 “핑 90% 개선” 같은 단일 벤치마크만으로 통과하지 않는다.

**효과가 없다면:** 성능 향상을 선언하지 말고 원인을 분리해 기술 가설·경로·워크로드를 변경한다. 보안/사용자 선택 가치가 있다고 해도 “가속”이라고 부르지 않는다.

## 5. Phase 3 — 안전하고 설명 가능한 Auto

### M3 — 자동 정책·사용자 정책이 충돌 없이 동작 (기존 A3)

**완료 후:** 사용자는 절약형/균형형/성능 우선형·사용자 지정 정책 중 선택할 수 있고, Auto는 사용자의 허용 범위 안에서만 실험·전환·복구한다.

**구현 묶음**
1. 관측 가능한 실제 경로 품질과 앱별 요구를 모델링한다. “좋다”라는 단일 지표 대신 지연·손실·완료율·연결 비용을 분리한다.
2. 정책 우선순위: **OS·인증·프라이버시 불변 조건 > 사용자 동의·엄격 모드·데이터 상한 > 서버 운영자 허용 정책 > 사용자가 고정한 앱/경로 설정 > Auto 추천**.
3. 안정형(검증된 경로), 균형형(작은 제한 실험), 적극형(사용자가 허용한 범위의 더 큰 실험)과 앱별·기능별 설정. 한 순간에 상충하는 프리셋이 동시에 적용되지는 않는다.
4. 샘플 부족·품질 변화 감지에는 히스테리시스, 시간/시도 횟수 상한, 백오프와 서킷브레이커, 실패 방법에 대한 쿨다운을 적용한다.
5. 기본 경로·기존 VPN 정책을 넘어서는 전환을 막고, 모바일 데이터/유료 서버 사용은 사전 승인 예산과 상한 내에서만 허용한다.
6. 최적화 실험은 작은 범위에서 시작하고 동일 작업 결과로 효과를 판정한다. 실제 개선 없으면 승격하지 않고 이전 검증 경로로 되돌린다.
7. 대시보드/로그에 현재 정책, 제안/실행/되돌림 이유, 배터리·데이터 비용, 거절된 설정 이유를 보여준다.
8. “엄격 차단”은 Android OS의 실제 always-on/lockdown·프로세스 종료/재부팅 시 누출 테스트를 통과하기 전에는 보안 보장으로 판매하거나 활성 보증하지 않는다.

**필수 PASS 증거**
- ON/OFF 동일 부하 테스트, 경로 플래핑 부정 테스트, 데이터 예산 초과/동의 철회/기존 VPN/실패한 서버/앱 종료 등에서 정책 위반 0건.
- 좋은 네트워크에서 “최적화하지 않는 편이 낫다”는 결정을 정당하게 내릴 수 있음.
- 정책 변경 → 실제 적용 → 효과/비용 확인 → 즉시 Stop/되돌림까지 실기기 증거.

## 6. Phase 4 — 서버 자가 운영과 커뮤니티 신뢰

**선행 구분:** M1에서 필요한 제한적 테스트 게이트웨이는 **실제 인터넷을 공개 중계하는 서비스가 아니다.** M4/M5는 운영자와 일반 이용자가 선택할 수 있는 안전한 생태계의 별도 출시 관문이다.

### M4 — 독립 운영 가능한 Linux/Ubuntu 서버

**구현:** 운영자 동의가 명시된 패키지 또는 컨테이너, 전용 비특권 사용자, 최소 권한·폐쇄 기본 바인딩, 서버 키/클라이언트 인증, TLS 수명주기/갱신, 설치·상태·업데이트·롤백·삭제, 대역폭/동시 사용자/CPU/RAM/요금/로그 보존 상한, 역할별 제한형 중계·진단·전송 기능, 공격성 목적지 차단/오류 처리.

**필수 PASS:** 외부 네트워크로 노출하지 않은 설치부터 운영자 명시 허용까지 추적; 허용되지 않은 익명 연결·목적지 거부; 자원 고갈 시 서비스 격리·중지; 재시작/업데이트/키 회전·폐기·복구와 안전한 완전 제거. 독립적으로 승인된 서버 1개로 첫 운영 게이트를 통과하되, 커뮤니티 출시가 아님.

### M5 — 검증 서버 디렉터리와 자원봉사 노드

**구현:** 서명되고 버전 관리되는 공식 검증 목록 + 수동 입력/자가 등록, 미검증 경고/명시 동의, 서버 신원·지역·수용량·비용/한도/프로토콜/검사 시각·신뢰 수준을 별도 표시, 폐기/이의 제기/키 교체, 오류·악용 신고, 운영자 비자발적 참여 방지.

**공식 검사 수준:** (1) 외부 프로토콜·TLS·상태 검사 → (2) 운영자가 직접 실행하는 서명/설정/무결성 검사 → (3) 동의 기반 최소 권한 상시 모니터. 운영자 승인 없는 파일 수집·원격 명령·은닉된 상주 제어 **금지**. 조작된 자기 보고나 시간 경과를 감안해 절대 안전 인증을 하지 않는다.

**필수 PASS:** 서로 독립적으로 승인받은 최소 2개 서버에서 조회·인증·경로 실패·키 만료/회전·폐기·서버 중단·비용 표시를 검증. 악성/위조 메타데이터·중복 신원·위험한 공개 프록시·개인정보 과다 로그를 거부하거나 경고하고 권한을 분리한다.

**미결 정책:** 감독자/검증키 소유, 수집·로그 보존, 이의 제기, 악용 대응, 지역별 법적 문제, 유료/기부 요금·환불·결제 도입. 결정 없이 실서비스를 배포하지 않는다.

## 7. Phase 5 — 사용자가 실제로 선택하고 신뢰하는 Android 제품

### M6 — UI, 설정, 모듈 및 지원 경험

**구현 묶음**
1. 기본 추천형 대시보드 + 사용자별 위젯·순서·숨김·바로가기 구성. *연결 상태/Stop/비용/개인정보 보호 상태는 숨기거나 잃어버릴 수 없게* 한다.
2. 간단/가이드/전문가 인터페이스. 사용자가 바꿀 수 없는 OS/신뢰 제약과 실제 지원되지 않는 항목은 분명하게 설명한다.
3. 옵션 기능 상태 구별: 미설치, 설치됨+OFF, ON, 지원하지 않음. OFF는 백그라운드 요청·리스너·작업을 종료한다.
4. **GitHub APK 유통 유지.** 하나의 APK에 들어 있는 실행 코드는 토글 OFF로 제거되지 않는다. 기본 앱 크기부터 최소화하고 리소스 다운로드는 선택 동의·해시/서명 검증. 실행 코드의 진짜 선택 설치/제거가 필요하면 Lite/Full, 서명된 split APK 배포 등 실제 설치/롤백 가능한 방식의 장단점과 사이즈를 먼저 실증한다. 임의 DEX를 내려받는 숨겨진 런타임을 만들지 않는다.
5. 기능 제거 중 파일·설정 보존 정책, 중단 중이던 전송, 네트워크 연결 세션, 캐시/로그 제거와 권한 폐기 처리.
6. **진단:** 기본 외부 전송 OFF, 제한된 로컬 로그, “복사/내보내기”, 보내는 필드·받는 사람·비용을 보이고 개별 제거·마스킹 후 별도 전송 승인. 미확정 수집 서버를 임의 설치하지 않는다.
7. 한국어/영어부터 접근성·저사양·오프라인 도움말·지역별 언어 확장을 검증하고, 인터넷 상태가 나쁜 사용자도 설정 화면에서 길을 잃지 않게 한다.

**필수 PASS:** 새 설치/업데이트/중단·재실행 후 설정/상태가 의도대로 유지. OFF/제거가 명확히 다르고, 저장 공간 절약은 실제 단말 측정 시에만 표시. 장애 상황에도 Stop·취소·진단 내보내기 접근 가능. 정확히 동의한 기록만 송신되고 취소는 전송하지 않음.

### M7 — 제한적인 GitHub 베타

**범위:** M1을 충족한 실제 Android 지원 경로와 M2에서 효과가 확인된 조건만 노출. M3/M4/M5의 **개별 지원 범위를 만족하는 기능만** 포함한다. 안전하게 동작하지 않는 기능은 OFF/미제공으로 남겨둔다.

**필수 PASS:** 릴리스 서명·소스/바이너리 출처·체크섬, 사전 동의 UI, 사용자 친화적 온보딩, 지원 대상·알려진 오류·VPN 상호 운용성 설명, 복구/다운그레이드 절차, 최소 2개 장치/OS 조합 등 *승인된 테스트 매트릭스*의 필수 케이스 검증, 사고 신고와 대응. 구체적인 지원 기기 수·지역·서명/지원 채널은 출시 전에 합의한다.

**실패 시:** 새 배포를 보류하고 기능 게이트 OFF 또는 이전 버전으로 되돌린다. 디버그/진단 APK와 일반 사용자 베타를 혼동하지 않는다.

### M8 — Android 안정판

**필수 PASS:** 지원 기기/OS 표에 해당하는 실환경 기능 검증과 회귀 테스트, 사용자 동의/보안/프라이버시 검토, 오래 실행·재부팅·전환/종료·배터리·저장공간 제한, 의도하지 않은 트래픽 노출·권한 상승·무제한 서버 중계·시크릿 노출에 대한 알려진 치명 결함 없음. 명확한 릴리스/복구 책임자와 공개 지원 정책·앱/서버 라이선스가 결정되어야 한다.

**유지보수:** 릴리스별 기능/지원 프로토콜/제약, 실기기 PASS/FAIL/NOT RUN, 사용자 불만과 재현, 설치·업그레이드 호환성, 공개 취약점 신고/패치 절차를 관리한다. 장애율·작업 성공률·자원 비용은 이용자 동의가 없는 중앙 텔레메트리 없이도 선택적/국소 측정으로 평가할 수 있어야 한다.

## 8. Phase 6 — 확장, 별도 기능과 글로벌 접근성

### M9 — 추가 플랫폼 및 기능별 독립 출시

- Android 안정판의 실제 수요와 검증된 이식 가능한 프로토콜만 기반으로 Windows/Linux를 각각 독립 구현/검증한다. Android 고객에게 불필요한 플랫폼 코드를 강제하지 않는다.
- 더 많은 앱/전체 기기 적용, 추가 프로토콜·멀티패스·커뮤니티 기능, 기기 간 전송 및 고급 프라이버시 기능은 **아래 E-게이트**로 각각 출시한다.
- 지역별 낮은 대역폭, 오래된 장치, 언어/읽기·접근성, 서버 운영 비용/지역 문제, 앱을 받기 어려운 조건을 실제 사용자 테스트로 검증한다.
- 글로벌 커버리지는 사용자 수나 지도 핀만으로 주장하지 않는다. 연결 성공·실제 작업 성과·운영자가 부담할 수 있는 비용·신뢰·지역별 제한을 함께 살핀다.

| **E5 프라이버시/제한망** | 허용된 별도 경로로 선택적 메타데이터 보호·접속 보조 | M3+M5 + 독립 위협 모델 | Tor 등 기존 생태계와의 합법·안전 호환 검토, 속도/익명성·로그/누출/지문·검열 위험 고지 |

| **E7 추가 운영체제** | Android와 독립적인 Windows/Linux 앱에서 검증된 기능 | M8 + 공통 프로토콜 규격 | OS별 경로/권한/방화벽/설치/업데이트/실제 통신 증거; 이름만 다른 래퍼 금지 |

**기능 후보는 무한히 열어 두되 구현은 무제한 동시 추진하지 않는다.** 각 새 기능은 사용자 문제, 1문장 완료 조건, 선행/보안/비용, 구현과 유지보수 대가, 중지/제거 수단을 정의한 뒤 우선순위를 매긴다.

## 9. 공통 검증 매트릭스와 실패 대응

| 테스트 축 | 최소로 다룰 경우 |
| --- | --- |
| 안전·권한 | 동의 거부/철회, 잘못된 선택 앱, 예기치 않은 전체 캡처, 다른 VPN 활성, 재시작/강제 종료/Stop 경쟁 |
| 네트워크 | 정상·혼잡·초저속, 높은 RTT/지터, 랜덤/버스트 손실, 완전 단절, Wi-Fi/셀룰러 전환, 캡티브 포털, 제한 프로토콜 |
| 트래픽 | DNS A/AAAA, IPv4/IPv6, MTU, TCP 생명주기, 지원되는 경우만 UDP/QUIC, 목적지 인증·단편화 |
| 개인정보·신뢰 | 위조 TLS/노드/디렉터리, 불량 서명/폐기, 토큰 누출, 불승인 업로드·전송, 로그 보존·삭제 |
| 데이터 정합성 | 중단 중복 전송/손상, 파일명·경로 공격, checksum, 서버/클라이언트 재시작, 저장 공간 고갈 |
| 리소스 | 종량제 상한, 저전력·저사양, 메모리/CPU·배터리, 무한 재시도/서버 폭주·오픈 프록시 방지 |
| 회귀 | 동일 소스 SHA, 음성·악화 사례, 여러 Android/OEM/버전, 업그레이드·다운그레이드, 이전 지원 기능 |

**합격 기록 표준:** 날짜 | repo/브랜치/full SHA | 빌드 ID | 기기/OS/앱 | 실제/가상/실험실 네트워크 | 작업과 성공 기준 | OFF/ON 결과·반복 횟수 | 로그(비식별) | PASS/FAIL/NOT RUN/BLOCKED | 부작용/롤백. 실험실 PASS는 실제 장치 PASS로 승격하지 않는다.

**Stop/rollback 공통 원칙:** 미동의 캡처, 엄격 모드 직접 누출, 무제한 외부 통신, 개인 로그/비밀 유출, 안전하지 않은 서버 접근, 데이터 손상 또는 재현되는 사용자 인터넷 완전 차단은 즉시 기능 비활성화와 원인 조사 대상. 이전 정상 버전/정책 복구 수단이 확인되기 전에는 확대 배포하지 않는다.

## 10. 실제 개발 순서 — 첫 구현 작업 패키지

아래 패키지는 PR 하나당 사용자 관점에서 검증 가능한 단위로 구현한다. 의도적으로 잘게 쪼갠 무의미한 PR 양산을 피하고, 큰 미완성 PR 한 개를 무조건 병합하지도 않는다.

| 순위 | 작업 패키지 | 종료 증거 / 연관 게이트 |
| --- | --- | --- |
| 1 | **현재 main + Draft PR #7 상태 대조**: 누락된 실제 A1 패킷 경로, TODO/죽은 코드, 실패·취소·보안 경계 파악 | 소스 기반 gap 리스트, 재현 가능한 실패 테스트, 진짜 코드 경로 |
| 2 | **M0 안전 기반 보완**: Android 설치·UI·Stop·VPN 공존/선택 동작 및 CI 재검증 | 정확한 SHA·기기 테스트/NOT RUN 기록 |
| 3 | **제한형 게이트웨이·인증 계약 검증**: 테스트 목적지·TLS/인증·정책 범위·쿼터 | 승인된 로컬/격리 서버에서 양·음성 테스트 |
| 4 | **TUN→DNS→TCP→TLS→실제 응답 단일 수직 경로 연결** | 실제 선택 앱 요청과 응답의 각 단계 추적·안전 실패 |
| 5 | **실기기 A1 독립 검증**: 비선택 앱, revoke/Stop, 전환/재시작/오류 | Android DEVICE PASS 또는 구체적 BLOCKER |
| 6 | **A1 회귀/자원·위협 테스트 강화**: IPv4/IPv6, MTU, 변조, socket recursion | 안전 게이트/이전 기능 비회귀 |
| 7 | **A2 벤치마크 설계와 기준선 고정**: OFF/ON 실제 브라우저 시나리오 | 재현 도구, 불량/정상망 프로필, 공개 가능한 비식별 샘플 |
| 8 | **A2 반복 현장/모의 실험**: 초저속·손실·단절·혼잡 | 효과/악화/비용 측정과 편향 분석 |
| 9 | **A3 Auto의 관측→제안→안전한 실행**: 예산·되돌림·플래핑 방지 | 사전 동의된 경로만 변환; 실제 작업 검증 |
| 10 | **M6 최소 UX**: 실측 상태·정책 설명·로그 복사/마스킹·기능 OFF | 화면+실환경 Stop/전송 없음 테스트 |
| 11 | **M4 승인된 서버 운영 시범**: 재현 가능한 비특권 Linux 설치/정지·쿼터 | 한 대 승인 노드의 회귀/악용 방지 |
| 12 | **M7 베타 범위·서명·지원 매트릭스 확정** | 지원 대상만 켠 GitHub 릴리스 준비 검토 |

**개발 리듬:** 각 회차는 “현재 SHA/게이트 확인 → 가장 가까운 실패 증거 확인 → 원인 수정 또는 완료 조건 충족 구현 → 자동 테스트/검토 → 문서·근거 기록 → 필요 시 Draft PR”을 순서대로 수행. 정상 동작하는 구조를 증거 없이 갈아엎지 않는다. 해당 게이트의 실제 장치 검증이 불가능한 회차는 다른 게이트를 완성했다고 주장하지 말고, 독립적으로 검증 가능한 안전 테스트·코드·문서 과제에 집중한다.

## 12. 의사결정이 남은 부분

**실행 전에 결정해야 하는 사항과 순서를 분리한다.**
- M1 현장 검증 전에: 사용자 승인된 실제 테스트 Android 기기, 외부 노출 없는 검증용 게이트웨이, 독립 HTTPS 목적지와 실험 허용 범위.
- M4/M5 일반 서버 네트워크 전에: 운영자 신원, 신뢰/검증 권한, 검사 도구 배포·업데이트·데이터·원격 권한, 노드 폐기·신고·법적 정책, 로그 종류/보존, 요금 제도.
- M6 이후 실제 설치 코드 절약 주장 전에: Github APK 배포에서 코드 구성 요소를 별개로 실제 제거하는 안전한 서명·업데이트 전략과 사용자 데이터 보존 정책.
- M7/M8 일반 공개 전에: 앱/서버 라이선스, 개인정보 처리와 지원/취약점 제보, APK 서명 및 신뢰할 배포 경로, 지원 기기/버전 기준.
- E5 프라이버시 확장 전에: Tor류 기술 포함 위협 모델, DNS·출구/웹사이트 로그·속도·지문 노출, 플랫폼 공존과 규칙·동의.

기존 [결정 등록부](DECISIONS.md)의 OPEN-001~008을 폐기하거나 자동 확정하지 않는다. 결정자는 프로젝트 소유자이고, 설계와 검증 제안은 구현자가 준비한다.
